# ADR 0035: 旅行プロフィールを端末内へ保存する

- ステータス: Accepted
- 日付: 2026-08-16

今回条件のTripContext正本は[ADR 0052](0052-establish-trip-v2-contract-and-migration.md)の
TripRequestへ移行する設計を採用した（#387で実装）。Profileの端末保存とprivacy境界は維持する。

## 背景

曖昧な旅行相談に答えるには 普段の出発地や同行者 好みを参照できる必要がある。一方で
今回だけの目的地や日程は 普段の嗜好とは分離しなければならない。

## 決定

- 普段の情報を`UserProfile`として`localStorage`の`transitforge.travel-profile.v2`へ保存する
- 今回の目的地 日程や条件は保存プロフィールへ混ぜず`TripContext`として扱う
- 初回登録は任意とする（#457で7ステップの必須初回表示を廃止）。マイ/プロフィールから確認 編集 取消 削除できる
- 生のプロフィールと`localStorage`の保存値をサーバーや外部旅行提供者へ送らない
- Agentへは出発地 同行者の要約 興味 旅行ペース 許容条件だけをallowlistで投影し
  現在旅程の要約とともに会話文脈として渡す
- 座標 生年月日 保存時刻 Entityの内部ID 予約URL 画像URLはAgent文脈へ含めない
- 今回の依頼と`TripContext`はプロフィール由来の既定値より常に優先する
- 興味や旅行ペース 許容度は将来の順位付けに使える0から1の値として保存する

## 影響

- アカウントなしで利用者ごとの初期条件を持てる
- 将来は`UserProfile`と会話から得た`TripContext`を候補生成へ渡せる
- Agentは登録済みの出発地や現在旅程を再質問せず利用できる
- Agent APIへ送る項目は型と回帰テストで固定し 意図しない項目追加を防ぐ必要がある
- 端末データを消去するとプロフィールも消える

## #457 互換拡張

同じv2/保存キーで未設定fieldを省略可能にする。既存の値を別の既定値へ変換せず、旧v2もそのまま読める。
普段の人数・優先移動手段と端末メモをoptionalで追加する。別Profile/Repository/クラウド同期は作らない。
自由記述メモの旧値は端末だけに保持する。#457追加指示により、利用者が項目ごとにAI送信へ同意して保存した場合だけ、各240文字/最大4項目を既存Agent Contextへ投影する。
モデルへの送信同意とログ保存は分離する。該当turnのTraceから自由文とTool payloadを除外し、サーバーのmodel-call Traceにも会話本文を残さない。今回条件を優先し、メモ内の命令やHTMLは実行しない。
人数はContextでusualPartySizeHintと明記し、TripPartyや予約人数へ自動昇格しない。
詳しくは[Profile編集契約](../architecture/travel-profile.md)を参照する。
