# 0005: JR西日本の列車混雑情報を低頻度キャッシュ経由で参照する

## Status

Accepted

## Context

列車番号に対応する車両別混雑情報を、列車上の棒グラフとして表示したい。
`https://www.train-guide.westjr.co.jp/api/v3/trainmonitorinfo.json` は、
列車番号をキーとして編成・車両ごとの `congestion` を返す。

このURLはブラウザ向けのCORS許可ヘッダーを返さず、公開された安定API仕様も
リポジトリには存在しない。また、表示の滑らかさのために短周期でアクセスする
必要はなく、大量アクセスを避けなければならない。

## Decision

- ブラウザは上流URLへ直接アクセスせず、同一オリジンの
  `/api/westjr/trainmonitorinfo.json` を参照する。
- ローカル開発ではViteミドルウェアが上流レスポンスを5分間メモリキャッシュする。
- 同時リクエストは1つにまとめ、複数タブや再読み込みによる上流アクセスを抑える。
- クライアントの更新間隔も5分とし、非表示タブでは更新しない。
- 利用者が混雑表示をオフにしている間も更新しない。
- 取得失敗後は15分待ってから再試行する。
- `congestion` が0以上の車両だけを合算し、列車番号単位の棒グラフへ変換する。
- 棒の高さには上限を設けず、混雑合計1あたり0.1mの線形スケールで表示する。
- 取得失敗や形式変更時は棒グラフを表示せず、列車表示そのものは継続する。
- 本番環境を追加する場合も、同等以上の共有キャッシュを持つ同一オリジンの
  プロキシを用意する。ブラウザから上流へ直接ポーリングしない。

## Consequences

- 開発サーバー単位の上流アクセスは、正常時に最大でも5分に1回となる。
- 現在の混雑情報とローカル時刻表の列車番号が一致した列車だけに棒が表示される。
- 上流レスポンス形式が変わると混雑表示は停止するため、パーサーのテストと
  失敗時の安全なフォールバックを維持する必要がある。
- Viteのメモリキャッシュはプロセス再起動で失われる。
