# ADR 0099: OTPで徒歩・バス経路を照会する

- ステータス: Accepted（初期のread境界のみ実装）
- 日付: 2026-09-28
- Issue: #756

## 決定

鉄道は既存のTransitforge時刻表インデックスを正本とし、徒歩のみとバス・徒歩の経路は、GTFS/GTFS-JPとOSMから構築したOpenTripPlannerのグラフを照会する。地図はMapboxで描画する。OTPが返す徒歩区間の時間と形状をバス経路の一部として維持し、異なるエンジンの徒歩見積もりと継ぎ合わせない。鉄道とバスはApplicationで複数の乗継駅を検討し、双方の時刻と徒歩時間が成立した場合だけ候補とする。公式アクセス案内は探索のヒントにとどめ、運行時刻の根拠にはしない。

## 境界と段階

最初のread Toolは認証済みTripの地点を出発点に限定し、任意の到着候補は未検証の座標とする。出発日時、GTFS対象期間、地点範囲、取得日、グラフ作成日、地図形状、予定時刻を明示する。対象外、検索済みで経路なし、検索障害を別状態にする。Tool応答だけでTripへ採用・確定しない。

OTPは常駐する別プロセスと、取得元・版・配布条件を確認したGTFSおよびOSMの再構築可能なグラフを要する。入力アーカイブのhash付き保存、グラフ生成、版付きS3配布はData Builderが所有する。Transitforgeはprivate subnetのFargateサービスとIAM Invoke限定のVPC Bridge Lambdaを所有し、VPC外のAgent LambdaからOTPを直接公開しない。AgentとBridgeは同じ固定versionのmanifestを検証する。ソースがない状態で全国対応や現在の運行保証を示さず、`current.json`だけで稼働版を切り替えない。

公開地図の経路はOTP区間のジオメトリのみを描き、出典と取得日時を表示する。未採用候補と保存済みTripの表示を区別する。引用された検索結果の公開画面表示は実装した。鉄道とバスの乗継候補の計算も駅カタログ・既存鉄道Tool・OTPを組み合わせて実装した。鉄道線形の公開地図表示とグラフ運用は後続実装とする。
