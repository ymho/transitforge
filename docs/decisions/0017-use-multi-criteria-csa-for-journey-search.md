# ADR 0017: 複数乗換検索に多目的CSAを使う

- ステータス: Accepted
- 日付: 2026-08-14

## 背景

乗換1回までの探索は直通列車インデックスから必要な列車だけを展開していた
乗換2回以上へ同じ方法を広げると候補の組み合わせが急増する

生成済みの`timetable-connection-index-v1`は1日約13万接続を出発時刻順に保持する
既存の接続走査は経路配列をラベルごとに複製し 全接続をリクエストごとに再ソートしていたため実データで30秒以内に完了しなかった

## 決定

- 乗換3回までの探索にConnection Scan Algorithmを使う
- バッチが出発時刻順に生成した接続をそのまま走査する
- 経路は親ラベル参照で復元し 走査中に経路配列を複製しない
- 駅と乗車回数ごとに到着が早いかつ出発が遅いParetoラベルを保持する
- ラベル数には上限を設け 最早到着と最遅出発を残してから優先条件で絞る
- 最初の到着候補から優先条件ごとの許容時間を超えた時点で走査を終える
- 最大乗換回数は3回とする
- 展開後の接続インデックスはLambda実行環境ごとに直近1件だけキャッシュする

乗換ペースは駅別標準乗換時間へ次の補正を行う

- 急ぐ: 標準の0.7倍 ただし最低2分
- 普通: 標準値
- ゆっくり: 標準値へ5分追加

経路優先は次の4種類とする

- バランス
- 早く着く
- 遅く出る
- 乗換少なめ

遅く出る候補は最速到着から45分以内で比較する
バランスは30分 早く着くは0分 乗換少なめは120分を探索上限に使う

## 影響

### 良い影響

- 乗換3回までを接続数にほぼ比例する時間で探索できる
- 同じ到着なら遅く出られる経路を候補にできる
- 利用者の移動速度と優先事項を分離して設定できる
- 探索件数 除外理由 適用条件をログから確認できる

### 悪い影響

- 全Pareto候補を無制限には保持しない
- 乗換時間の駅別値はdata-builderの知識追加が必要
- 運賃 ホーム位置 混雑度は順位へ含めない

### リスク

- 最速到着からの許容時間外に利用者に適した経路がある可能性がある
- 接続インデックスの並び順が契約から外れると探索結果が不正になる
- 駅別乗換時間が未設定の駅では既定5分を使う

## 確認

- 2回乗換を含む経路を復元できること
- 急ぐ 普通 ゆっくりで乗換可否が変わること
- 早く着くと遅く出るで順位が変わること
- 実データで候補と探索時間を確認すること
- 当日だけ遅延 行き先変更 運休を反映すること

## 置き換えるADR

ADR 0015を置き換える
