# ADR 0002: 初期WebビューワーにViteとTypeScriptを使用する

- ステータス: Accepted
- 日付: 2026-07-12
- 決定者: TransitForge開発者

## コンテキスト

初期ビューワーには、Mapboxを表示し、ローカル開発時に素早く検証できるWeb開発基盤が必要である。
現時点では、列車の3D描画方式、UIフレームワーク、バックエンド構成は未決定である。

## 決定要因

- TypeScriptで入力契約と地図表示の境界を明確にする。
- 小さなWeb画面をローカルで速やかに起動・検証できる。
- UIフレームワークを早期に固定しない。
- Mapbox GL JSをモジュールとして読み込める。

## 検討した選択肢

### Viteと素のTypeScript

Viteを開発・ビルド基盤とし、画面は素のTypeScriptとCSSで開始する。

### UIフレームワークを含む構成

ReactなどのUIフレームワークを初期段階から導入する。

### CDNのみの単一HTML

パッケージ管理を使わず、HTMLからMapbox GL JSを直接読み込む。

## 決定

初期WebビューワーにはViteとTypeScriptを採用し、UIフレームワークは導入しない。
Mapbox GL JSはnpmパッケージとして使用する。

この決定は、Three.jsの採用、列車レンダラー、UIフレームワーク、データ読み込み方式を確定しない。

## 影響

### 良い影響

- 型検査と本番ビルドを早期から実行できる。
- 最小のMapbox画面を短い開発ループで検証できる。
- 将来のUIフレームワーク導入を必要になるまで保留できる。

### 悪い影響

- Node.jsとnpmの開発環境が必要になる。
- UIが複雑になった場合、後でフレームワーク採用を判断する必要がある。

### リスク

- 大容量の入力JSONをそのままブラウザで読み込むとメモリ使用量が大きくなる。
- MapboxとThree.jsの統合は別途プロトタイプで検証が必要である。

## 検証

- `npm run build` が型検査と本番ビルドを完了できること。
- `.env.local` の公開トークンで、Mapbox Standardの3D建物を表示できること。

## 置き換える決定

なし。
