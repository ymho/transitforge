# ADR 0073: 根拠付き旅行案を構造化選択から描画する

- ステータス: Accepted
- 日付: 2026-09-21
- 関連: #376、ADR 0026 / 0031 / 0044 / 0072

## 決定

一般旅行相談の最終回答に、一時的な`travel-plan`表示契約を追加する。
モデルは候補資料と抜粋、定型の過ごし方、4カテゴリのAI概算、写真Evidenceを選ぶ。
Applicationが検証後に、日別行程、前提と合計を含む概算、出典付き写真を一つの回答へ描画する。

`travel-plan`はTrip、TripUpdateProposal、CostProposalの正本ではなく、保存や予約を伴わない相談回答である。
既存Tripがある場合の費用保存・利用者確認は、引き続き`propose_trip_costs`が担当する。

## 理由

ADR 0072のLive比較では、両モデルとも必要な調査後に行程と概算を生成できたが、一般回答の
Evidence presenterが自由文を破棄したため、利用者には資料抜粋しか届かなかった。自由文をそのまま許可すると、
未確認の時刻、価格、営業、写真URLをEvidence IDだけで正当化できてしまう。

そこで、検証可能な資料と写真はEvidenceへ固定し、非事実の計画判断は定型activityと明示的なAI概算へ限定する。
合計と日本語本文はApplicationが生成するため、モデルの計算誤りや出典の付け替えも表示境界で拒否できる。

## 影響

- 目的地指定時は1候補以上、目的地未定時は2〜3候補を同じ契約で提示できる。
- 起点が不明でも、起点交通を概算外と明記して質問票に戻らず提案を出せる。
- 写真は候補とのsource binding、HTTPS、hotlink可、attribution、掲載元をすべて満たす場合だけ表示する。
- Web検索だけで候補回答を完了せず、利用可能な地点照合・写真取得能力へ進む。取得不能を確認した場合は写真なしでも提案全体を継続する。
- 発話と計算済み相対日付のどちらにも出発日がない場合、`startDate`は`null`として扱い、当日などを補完しない。
- 構造化結果が検証に失敗した再試行では、許可リスト内の検証理由だけをモデルへ返す。元のモデル出力やEvidence本文はエラーとして反射しない。
- `travel-plan` / `source-explanation`本体が検証できる場合、付随するdecision summaryのEvidence ID不整合だけを理由に本体を破棄しない。本体内の参照は各presenterが改めて厳格に検証する。
- 任意の自由記述行程は許可しない。より細かな時刻入り旅程は、既存のJourney/Trip ToolとProposalで扱う。
- 既存のsource-explanation、InTripAnswerPlan、CostProposalの責務は変更しない。
