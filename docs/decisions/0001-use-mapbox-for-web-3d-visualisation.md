# ADR 0001: Webベースの3D可視化にMapboxを使用する

- ステータス: Accepted
- 日付: 2026-07-12
- 決定者: TransitForge開発者

## コンテキスト

TransitForgeは、計画上の列車運行を魅力的な3D表示で見せることを目指している。
リアルな建物は、その体験を構成する重要な要素である。本プロダクトはWebアプリケーションとし、
2D、3D、Web以外の提供方式を同等の選択肢としては扱わない。

この決定では、プロダクトレベルの可視化に関する制約を確定する一方、列車描画の詳細な構成は、
実測に基づいて評価できるよう未決定のままとする。

## 決定要因

- ビューワーをWebアプリケーションとして提供する。
- 3D表示を体験の中核とする。
- リアルな建物を視覚的な背景として使用する。
- 列車を3Dモデルとして描画できるようにする。
- 実際の全量入力データに対して性能を検証する。

## 検討した選択肢

### Mapboxと互換性のある列車3Dレンダラー

地図、地形、建物の表示にMapboxを使用する。列車の3D表示には互換性のあるレンダラーを
評価し、Three.jsを最有力候補とする。

### 2Dまたは模式図のビューワー

必要とする3D建物表示を持たない、平面地図、キャンバス、または模式図を使用する。

### Web以外の3Dアプリケーション

Webアプリケーションではなく、ネイティブアプリケーションまたはゲームエンジンを使用する。

## 決定

TransitForgeは3D表示を行うWebアプリケーションとし、地理的な可視化とリアルな建物の
背景表示にMapboxを使用する。

この決定では列車レンダラーを確定しない。Three.jsを最有力候補とし、採用前に、実測した
代表的な負荷を使用する小規模な統合プロトタイプで評価する。

## 影響

### 良い影響

- 実装開始前に、目指す視覚体験が明確になる。
- 全量データのMapbox描画を実用化する観点で計測を行える。
- 固定された地図環境を前提に列車レンダラーを評価できる。

### 悪い影響

- 実装がMapbox固有の機能と利用条件に依存する。
- ブラウザとGPUの性能が重要な制約になる。

### リスク

- 経路の全形状または同時運行する全列車モデルは、前処理やバッチ描画なしではブラウザの
  実用的な描画能力を超える可能性がある。
- Mapboxと採用する列車レンダラーの間で、カメラ、座標、奥行き、操作を同期する必要がある。
- 実装前に、Mapboxのプラン、トークン、スタイル、データ利用条件を確認する必要がある。

## 検証

- 全量入力のファイルサイズ、形状数、最大同時運行列車数を計測する。
- 代表的な経路形状と3D列車数を使用して、Mapbox上でプロトタイプを作成する。
- 座標とカメラの同期、奥行き、向き、選択操作、フレーム時間を検証する。

## 置き換える決定

なし。
