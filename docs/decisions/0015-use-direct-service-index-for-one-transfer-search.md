# ADR 0015: 直通列車インデックスで乗換1回まで探索する

- ステータス: Accepted
- 日付: 2026-08-14

## 背景

ADR 0011では最初の経路検索を直通に限定し 乗換探索を後続フェーズとした
直通検索の通し確認後に接続インデックス全体を走査したところ 1営業日あたり約14万接続を扱い
Lambdaの検索に約7秒から9秒かかった

一方 `direct-service-index-v1`は各列車の順序付き停車駅と駅別の出発可能列車を持つ
乗換1回であれば出発駅の列車と その停車駅から出発する列車だけを展開できる

## 判断要因

- 収録路線内で乗換1回の候補を実用的な応答時間で返せること
- 直通候補を引き続き比較対象に含めること
- 遅延を乗換可否と発着時刻へ反映できること
- 探索過程をドメイン知識で検証できるログがあること
- 乗換2回以上へ拡張する余地を失わないこと

## 選択肢

### 接続インデックス全体を走査する

任意回数の乗換へ拡張しやすいが 乗換1回の現在要件に対して走査量と応答時間が大きい

### 直通列車インデックスから必要な列車だけを展開する

探索範囲を出発列車と乗換駅の出発列車へ限定できる
乗換回数は1回までとなるが現在の要件に一致する

## 決定

AI駅員の経路検索は`direct-service-index-v1`を使い 直通と乗換1回の候補を同時に探索する

- 乗換時間は既定5分とし 駅固有の例外を一か所で定義できるようにする
- 列車別遅延を各区間の発着へ加え 遅延後の時刻で乗換可否を判定する
- 順位付けは到着時刻へ乗換1回あたり10分相当の負担を加える
- 10分は比較用の値だけに使い 利用者へ示す実際の発着時刻と待ち時間は変えない
- 直通のみを求める呼び出しは`maxTransfers=0`で同じ探索器を使う
- `timetable-connection-index-v1`と既存の接続走査は乗換2回以上の将来拡張用に維持する

検索ログには候補数 除外理由 乗換駅 待ち時間 採用した全区間を記録する

## 影響

### 良い影響

- 乗換1回を全接続走査より小さい探索範囲で扱える
- 直通と乗換を同じ基準で比較できる
- 乗換時間や順位の判断を構造化ログから追跡できる
- 直通検索のAPI契約を維持しながら候補へ複数区間を追加できる

### 悪い影響

- 乗換2回以上は探索できない
- 運賃 ホーム間距離 列車ごとの接続保証は順位へ反映しない
- 駅固有の乗換時間は知見が得られるたびに追加する必要がある

### リスク

- 駅名の表記揺れがあると乗換駅を同一視できない
- 乗換負担10分が利用者の好みと一致しない場合がある
- 遅延情報がない未来日は計画時刻だけで評価する

## 確認

- 直通と乗換1回が混在するテストで順位と全区間を確認する
- 5分未満の乗換を除外し 遅延後の待ち時間で再判定する
- `maxTransfers=0`で直通だけを返すことを確認する
- 実データで直通区間と乗換必須区間を検索し 応答時間とトレースを確認する

## 置き換えるADR

なし

ADR 0011の直通限定フェーズを完了し 次の段階として拡張する
