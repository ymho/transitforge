# 0007: Bedrockへ渡す前に混雑時系列を決定的に集計する

## Status

Accepted

## Context

DynamoDBには、JST日付ごとに最大1,440件の毎分混雑サマリーがあり、全列車合計と
列車番号別合計を保持している。日次ピークだけでなく、1時間ごとの推移、混雑した路線、
種別・列車名・行き先を含む混雑列車をAI駅員から確認したい。

毎分項目やS3生データをそのまま基盤モデルへ渡すと、入力サイズ、推論コスト、計算結果の
再現性が悪化する。一方、列車の種別・行き先と行き先側路線は、すでにブラウザが読み込む
列車・駅路線カタログから判定できる。

## Decision

- DynamoDBの毎分サマリースキーマと、S3を正本とする境界は変更しない。
- Lambdaは指定JST日付の毎分サマリーをQueryし、日次ピーク、JSTの24時間バケット、
  列車番号別の観測中平均・日次寄与平均・ピークを決定的に計算する。
- 未観測時間は混雑ゼロとして扱わず、観測件数とnullの分析値を返す。
- ブラウザは列車番号とピーク時刻を既存時刻表へ結合し、種別、列車名、行き先、既存の
  車体色判定と同じ行き先側路線名を付加する。
- 路線順位は列車の日次寄与平均を行き先側路線ごとに合算する。路線未判定の列車は順位から
  除外し、未判定件数を別に返す。
- Bedrockへ返すツール結果は、24時間の圧縮済み推移、上位5路線、上位5列車、日次ピークに
  限定する。全列車統計と毎分データはモデルへ渡さない。
- 既存の`daily_congestion_peak` API操作は、デプロイ切替中の旧ブラウザ互換のため維持する。

## Consequences

- 既存の最大730日分のサマリーを再収集・再保存せず、直ちに時系列分析へ利用できる。
- 集計値は同じ入力から常に同じ結果になり、Bedrockは説明と質問解釈に集中できる。
- DynamoDBの書き込み件数と項目サイズは増えない。
- 路線順位は現在走行中の区間ではなく、行き先側路線による分類である。
- 列車番号が時刻表と一致しない場合、列車は混雑順位へ残るがメタデータと路線は未判定になる。

## Validation

- UTCの毎分項目が正しいJST時間へ集計されること。
- 観測中平均、日次寄与平均、ピークが独立して計算されること。
- 同じ列車番号の候補が複数ある場合、ピーク時刻に運行中の列車を優先すること。
- Bedrockへ返す結果が上位件数とツール結果サイズの上限内に収まること。

## Supersedes

ADR 0005の「Bedrockへピーク観測と上位5列車だけを返す」境界を、本ADRの圧縮済み
日次・時間別・路線別・列車別分析へ置き換える。収集頻度、S3正本、DynamoDB毎分サマリーの
決定は変更しない。
