# ADR 0003: 開発時にローカルのビューワー入力を配信する

- ステータス: Accepted
- 日付: 2026-07-12
- 決定者: TransitForge開発者

## コンテキスト

全量入力はリポジトリに含めないローカルJSONであり、合計サイズも大きい。初期ビューワーは
ローカル環境でこれらを読み込む必要があるが、ビルド成果物へ入力を複製してはならない。

## 決定要因

- `viewer-input/` をGit管理・ビルド成果物から除外する。
- ブラウザから既存の入力契約どおりに2つのJSONを取得できる。
- 入力への書き込み、変換、補正を行わない。
- 本番運用方式を早期に固定しない。

## 検討した選択肢

### Vite開発サーバーのローカル配信ミドルウェア

開発サーバーが固定された2ファイルを読み取り専用で配信する。

### `public/` ディレクトリに入力を置く

入力をアプリケーションの静的ファイルとして扱う。

### ブラウザのファイル選択UI

利用者が起動のたびに2つのJSONを選択する。

## 決定

開発中はViteミドルウェアが `viewer-input/train_index.json` と
`viewer-input/path_catalog.json` を読み取り専用で配信する。

この決定は開発時のローカル入力に限定する。本番配信、データ更新、キャッシュ、認可の方式は
未決定とする。

## 影響

### 良い影響

- 実データをコピーせず、入力契約に近いURLで読み込める。
- 全量入力をGitとビルド成果物から除外できる。

### 悪い影響

- 現時点の入力読み込みは開発サーバー起動時に限定される。

### リスク

- 全量JSONのブラウザ読み込みとGeoJSON変換は、メモリと初期表示時間に影響する。

## 検証

- 経路カタログを読み込み、全経路をMapbox上に追加できること。
- 入力ファイルがGit管理・ビルド成果物に含まれないこと。

## 置き換える決定

なし。
