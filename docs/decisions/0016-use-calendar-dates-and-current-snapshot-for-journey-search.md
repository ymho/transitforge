# ADR 0016: 経路検索の日付を暦日で受け取り現在検索だけ運行情報を適用する

- ステータス: Accepted
- 日付: 2026-08-14

## 背景

利用者は日付を暦日として指定し 4時境界の業務日付や平日と土休日のダイヤ種別を意識しない
一方 日付別の生成済みインデックスは業務日付と24時を超える時刻で構成される

運行スナップショットは検索時点の状況を表すため 未来日や過去日の計画へ適用すると誤った遅延や運休になる
経路候補を平文だけで返すと複数候補と乗換区間を比較しにくい

## 判断要因

- 利用者が暦日だけを意識すればよいこと
- バッチ生成済みの日付別ダイヤを正本にすること
- 未来日へ現在の遅延を混ぜないこと
- 地図と経路検索が同じ最新運行スナップショットを参照すること
- 複数候補と途中停車駅を小さい画面でも比較できること

## 決定

- 利用者が指定した日付は日本時間の暦日として解釈する
- 4時未満の時刻は前日の`serviceDate`と24時を超える時刻へ変換する
- 平日と土休日を検索側で推測せず 対象`serviceDate`の生成済みインデックスをそのまま使う
- 日付指定がなければ日本時間の実日付を検索条件にする
- 最新`delays.json`は現在の業務日付かつ収集時刻と検索時刻が現在から5分以内の場合だけ使う
- 取得失敗がある 古い 読み込めないスナップショットは適用せず計画ダイヤへ戻す
- 運行情報を使う場合は遅延を発着時刻へ加え 行き先変更後の区間を正とする
- スナップショット時刻に運行中であるはずなのに存在しない列車は運休として候補から除外する
- 未来日と過去日は運行スナップショットを読まず計画ダイヤだけで検索する
- 経路候補は構造化レスポンスからタブと縦型タイムラインを描画する
- 各列車区間は路線色で結び 展開時に途中停車駅と時刻を表示する

## 影響

### 良い影響

- 「8月15日2時」のような入力を利用者の感覚どおり扱える
- 曜日判定の重複を避け data-builderの生成結果を一貫して参照できる
- 未来日の検索では遅延用DynamoDBを走査せず負荷を減らせる
- 地図と経路案内のリアルタイム適用条件が揃う
- 複数候補の区間と乗換を視覚的に比較できる

### 悪い影響

- 現在時刻から離れた当日検索にはリアルタイム情報を適用できない
- 日付別インデックスが欠けている日は検索できない
- 路線カタログだけで区間の路線を一意に判定できない場合は中立色になる

### リスク

- 年を省略した月日が現在日から大きく離れる場合は意図した年と異なる可能性がある
- 運行スナップショットに未発車列車が含まれないため 不在を一律に運休扱いできない
- 行き先変更先が時刻表の停車駅列にない場合は経路を安全に切り詰められない

## 確認

- 金曜から土曜の日付指定で土曜日の生成済みダイヤを参照する
- 4時前の暦日指定が前の業務日付と24時超時刻になることを確認する
- 未来日検索で運行スナップショットを読まないことを確認する
- 新鮮で完全な現在スナップショットだけが遅延 行き先変更 運休へ反映されることを確認する
- 3候補のタブ切り替えと途中停車駅の展開をデスクトップとモバイルで確認する

## 置き換えるADR

なし

ADR 0014とADR 0015を経路検索へ適用する判断として追加する
