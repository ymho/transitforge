# ADR 0010: 日次入力を4時に切り替え、代表ダイヤだけをAI用に保持する

- ステータス: Accepted
- 日付: 2026-08-01

## コンテキスト

ビューワーの営業日は4:00に切り替わる一方、時刻表取得は3:00に開始する。
生成直後に固定キーを上書きすると、3時台だけ前日扱いの画面へ当日ダイヤが入る。
また、駅・路線カタログを独立オブジェクトとして必須取得すると、その削除だけで
ビューワー全体が起動できない。AIには平日と土休日の差を調べる必要があるが、全日分の
ダイヤを保存する必要はない。

## 決定

- 3:00のECSタスクは当日ダイヤを生成し、非公開S3の日付付きprefixへ2ファイルを置く。
- 4:00の別ECSタスクは当日分が両方存在する場合だけ、Web用S3の固定キーへ昇格する。
- 駅・路線所属カタログは`train_index.json`へ内包し、viewer-inputは2ファイルに限定する。
- 移行中に内包カタログがない場合もビューワーは起動し、未判定色をグレーにする。
- 祝日判定を含め、平日と土休日の最新代表ダイヤを非公開S3の固定2キーへgzip保存する。
- AI Lambdaが代表ダイヤを決定的に検索し、最大5件だけをBedrockへ返す。全ダイヤは
  ブラウザにもモデルにも送らない。
- 代表ダイヤの旧S3バージョンと日付付きステージは短期ライフサイクルで削除する。

## 影響

- 3時台の営業日と公開データの不一致を避けられる。
- 3:00の生成失敗時は4:00の昇格も失敗し、前日の正常な固定キーが残る。
- viewerは`station_line_catalog.json`へ依存しない。
- AIは「平日の10時ごろ大阪に着く特急」のような代表ダイヤ検索を実行できる。
- 代表ダイヤは運行実績ではなく、保存された代表日の計画情報として回答する。
