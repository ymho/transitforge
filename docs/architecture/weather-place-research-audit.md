# 天気と候補調査の監査（2026-09-09）

## 範囲

直近デプロイ後の非公開Feedback 6件、Agent Trace 6件、model-call record 27件を照合した。
同一会話の複数評価・呼び出しを含み、独立した相談件数ではない。生会話、コメント、識別子、
providerRequest、認証情報は公開しない。Issue #365、#366、#367で追跡する。

## 確認できた原因と修正

| Issue | 原因 | 変更 |
| --- | --- | --- |
| #365 | 天気URLが`forecast_days`と`start_date/end_date`を併用し、Providerが400を返す | 日付指定と日数指定を排他化。片側の日付、現地日付、実在する暦日、予報範囲を検証する |
| #366 | 近場検索に混ざる似た地名の別地域を再評価せず、候補へ進む | 当時の500文字制限に合わせWeb検索descriptorを短くし、所在地照合・不一致時の再探索・移動負担の不確実性と末尾の責務境界を含めた。後続変更で500文字切り詰め自体は廃止した（ADR 0044） |
| #367 | Web本文未取得で失敗した地点照合が、本文取得後も同じ失敗のキャッシュを返す | 状態依存の`precondition_failed`を分離し、別Toolの成功後のみモデルによる再評価を許可する |

公開地点の天気URLを直接照会し、修正前の排他パラメーターエラーと、修正後の対象日24時間分の
取得成功を確認した。予報の真偽や将来の的中率を保証する検証ではない。
[Open-Meteo仕様](https://open-meteo.com/en/docs)に従い、日付なしは7日間、指定日は現地の今日から
15日後までとする。当初は所在地の単独の市区町村名を要求したが、後続変更で市名＋行政区名の
表記をProvider Adapterで市へ正規化する。施設名や番地から市を推測しない。取得不能を晴れ等へ補完しない。

Issue #306の境界は維持する。地域の意味解釈と再探索の判断はBedrockに残し、発話router、
固定調査順序、常時Reflectionを追加しない。モデル、生成tokens、実行上限、timeout、Evidenceと
Viewer Actionの検証は変更しない。前提不足の解除でも、別の恒久的エラーによるTool除外は維持する。
