# 旅程条件の単一正本化（#761）

Parent: #753 / Epic #751

## 第1段階: Adapterの偽の受理判定を撤去

Strands Adapterは条件のtargetだけを見て成功を返さない。全ての条件操作を
Applicationへ渡し、受理結果だけで同じ実行中のEffectiveIntentを更新する。
Applicationの明示的な拒否はToolのエラーとして返し、不確かな保存失敗では
後続readと回答公開を止める。回数上限・モデル・プロンプト・Tool schemaは変更しない。

同じ内容を再送したか、本当の別変更かを判定するのは永続化境界の責務であり、
Adapter側にMapやSetの別正本を作らない。

## この段階ではまだ未完了

既存Repositoryのtarget別receipt契約はこの段階で変更していない。
そのため本差分だけで同一ターン内の異なる訂正が永続化できるとは扱わない。
Trip.requestへの原子的採用、部分条件の保存、手動編集後のoverlay再適用防止、
条件パネル/旅程/次回AI参照の一本化は後続実装。#761/#753は閉じない。
関連する#740のAdapterキャッシュ案は取り込まず、更新判定の責務をApplicationへ戻す。

## 確認

実Strands SDKと合成モデルで、同一targetの異なる受理値、撤回、Application拒否、
不確かな2回目の保存結果、拒否後の再解釈を確認する。追加5件中4件は変更前に失敗し、
変更後は全て成功した。既存の反復試験もApplicationへの委譲を期待する契約に更新した。
Adapter23件と既存Application5件の対象試験は28件成功。

これは実モデルの会話品質・反復解消や、Tripへの実保存を証明するテストではない。
全体CIとは結果を分ける。旧履歴の移行・データ削除・AWS設定変更は行わない。
