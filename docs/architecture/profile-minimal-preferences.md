# 最小の「いつもの好み」プロフィール

2026-09-26。利用者の「プロフィールはもっと減らしてよい」という指示に基づく。条件更新 #716 / #724とは独立して反映できる変更。

## 画面とAI参照の範囲

プロフィールは任意の4セクションへ縮小する。

1. 普段の出発地: 駅・エリアを1つの入力欄で扱う。
2. 興味: 既存の興味選択を再利用する。
3. ペース: 1日の過ごし方だけ。細かい許容度フォームは置かない。
4. 配慮してほしいこと: 宿泊・食事・避けたいことの任意メモ。各項目のAI利用許諾は個別に維持する。

移動手段・車の有無・歩行/乗換/混雑/早朝/深夜/運転/バスの許容度は常設フォームから外す。単に隠すだけでなく、user profileからEffective Intentへ投影する参考情報からも外す。移動に関する今回の希望は各旅行の条件として扱う。人数、同行者、子どもの情報、予算、旅行ごとの移動上限をプロフィールから現在の条件へ自動確定しない。

## 保存と同意

サーバーProfile API、CAS、自動保存、IME対応、session generation境界をそのまま使う。別のプロフィールDBや保存frameworkは追加しない。

保存済みの旧詳細値はこの変更では削除しない。他項目を編集しても非表示の値はround-tripされる。普段の出発地を編集しない限り旧station/areaも保持する。利用者が出発地を明示的に変更・削除した場合だけ、その1欄が表すstation/areaを一緒に変更し、削除後に隠れたareaを復活させない。

AI利用許諾のないメモはContextへ送らない。プロフィールの値はreference_onlyの参考情報であり、今回の受理済み条件より優先しない。会話の条件変更でProfileへ書き込まない。会話からの恒久更新Toolは本変更の範囲外。

## 検証

- 4セクションと削除対象の入力欄不在
- 連続編集/IME/session clearの既存テスト
- 非表示の移動・同行者・予算・メモ・同意値が無関係な編集で消えない
- 出発地の明示削除で隠れたareaが復活しない
- 未許諾メモ/非表示の旧許容度がAI入力へ入らず、元Profileは変更されない
